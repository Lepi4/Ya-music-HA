# Обзор Yandex Music API

Полный отдельный аудит Rotor и «Моей волны», включая второй session-уровень:
[my-wave-api-audit-2026-11-09.md](my-wave-api-audit-2026-11-09.md).

Дополнение 2026-11-09 / 0.3.2: подключены `rotor_station_info`,
`rotor_station_settings2`, `rotor_station_feedback` и продолжение
`rotor_station_tracks(queue=...)`. Настроения берутся из `restrictions2`,
волна по текущему треку использует `track:<id>`. Отдельные сеансы колонок
живут в HA; нативный режим волны станции не запускается. Ниже сохранён
результат исходного обзора 0.3.1, включая его границы проверки.

Проверка: 2026-11-08. Библиотека `yandex-music` 3.2.0. Полный перечень 163
публичных методов в 22 группах: [api-surface.json](api-surface.json).
Перечень включает чтение и изменение данных; наличие метода не гарантирует,
что он доступен любому аккаунту или типу подписки.

Источники: [библиотека API](https://github.com/MarshalX/yandex-music-api),
[провайдер для Music Assistant](https://github.com/trudenboy/ma-provider-yandex-music).
Проверялись реальные ответы музыкального API подключённого аккаунта. При обзоре
не изменялись лайки, история, настройки волны, очереди и воспроизведение.
Аккаунт, токен, идентификаторы устройств и содержимое личной истории в отчёт не включены.

## Что уже доступно в интеграции

| Возможность | Метод / источник | Проверка |
|---|---|---|
| Аккаунт и подписка | `account_status` | HTTP 200; используется существующий токен колонки |
| Главная и персональные подборки | `landing`, `landing3` | HTTP 200; названия и карточки берутся из ответа |
| Собственные плейлисты и треки | `users_playlists_list`, `users_playlists` | Открытие проверено |
| Любимые треки | `users_likes_tracks`, `tracks` | Проверены заполненная и пустая коллекции; пустой batch исправлен в 0.3.1 |
| Поиск | `search` | Треки, альбомы, плейлисты, подкасты и выпуски |
| Альбомы и главы | `albums_with_tracks` | Открытие альбома проверено |
| Подкасты | `podcasts`, `albums` | HTTP 200, каталог и карточки |
| Аудиокниги | `search(type_=podcast)`, `users_likes_albums` | Отбор по `type/meta_type=audiobook`, отдельный раздел в 0.3.1 |
| Моя волна | `rotor_station_tracks` | Выдача треков проверена; полноценная обратная связь ещё не подключена |
| Чарт | `chart` | Получение треков проверено |
| Состояние и управление колонкой | Home Assistant + Yandex Station | Отдельный контекст колонки и настоящий `source_list` |

Отдельного рабочего `landing3/audiobooks` в проверенном API не найдено (404).
Поиск с `type=album` по слову «аудиокниги» возвращает также музыку и саундтреки;
это не подходящий способ классифицировать книги. Реальные книги встречаются
в `podcasts` с сочетанием `type=audiobook`, `metaType=podcast`. Такой результат
открывается как альбом, его треки — главы. Это каталог Яндекс Музыки, а не
подключение всего сервиса Яндекс Книг или произвольных навыков Алисы.

## Полезное, подтверждённое чтением API, но ещё не подключённое

| Возможность | Ответ при проверке | Что можно добавить |
|---|---|---|
| История прослушивания | `music_history`: 200, вкладки истории | «Недавно слушали», переход к альбому/плейлисту/волне |
| Тематические подборки | `metatags`: 200, четыре дерева | Навигация по жанрам, настроению, занятиям и эпохам; названия брать из API |
| Жанры | `genres`: 200 | Дерево жанров и переходы к подборкам |
| Радиостанции | `rotor_stations_dashboard`, `rotor_stations_list`: 200 | Персональная панель радио и каталог станций; в проверке вернулось 700 записей |
| Избранные альбомы | `users_likes_albums`: 200 | «Мои альбомы», раздельные книги и подкасты в коллекции |
| Избранные исполнители | `users_likes_artists`: 200 | Страница исполнителя и его дискография |
| Добавленные чужие плейлисты | `users_likes_playlists`: 200 | Объединить с собственными плейлистами без дубликатов |
| Закреплённое | `pins`: 200, пустой список | Быстрые плитки любимых источников на главной |
| Новые и ожидаемые релизы | `users_presaves`: 200, пустые списки | Раздел ожидаемых/вышедших релизов |
| Нежелательные треки | `users_dislikes_tracks`: 200 | Просмотр ограничений и дальнейшая поддержка дизлайков |
| Подсказки поиска | `search_suggest`: 200 | Подсказки названий и исполнителей при вводе |
| Последняя волна | `rotor_wave_last`: 200 | Возврат к последнему контексту волны |
| Лента | `feed`: 200 | Дополнительные персональные плейлисты и события |

Пустой список в этих API — нормальный результат и должен отображаться без ошибки.

## Есть в библиотеке, требует отдельной реализации и проверки

| Группа | Методы и ограничения |
|---|---|
| Исполнители | `artists_brief_info`, `artists_tracks`, `artists_discography_albums`, `artists_similar`, ссылки и сведения |
| Похожие записи | `tracks_similar`, `albums_similar_entities`, `playlist_similar_entities`, рекомендации плейлиста |
| Тексты песен | `track_supplement`, `tracks_lyrics`; наличие зависит от трека, lyrics требует подписанного запроса |
| Подробные сведения | `tracks_full_info`, `tracks_credits`, labels, disclaimers; авторы, исполнители, предупреждения |
| Прогресс книг и прослушивания | `play_audio`, позиции в моделях; запись истории нельзя подменять простой загрузкой аудио |
| Бесконечная волна | Rotor feedback и session cursor; нужны события start/finish/skip, а не повтор одного пакета треков |
| Качество потока | `tracks_download_info`, `tracks_file_info`; выбор внешнего URL не меняет автоматически качество нативного `playMusic` колонки |
| Облачная очередь | `queues_list`, `queue`; сырой GET без device header вернул 400. Нельзя считать этот API очередью любой станции |
| Видеоклипы | clips, credits, персональные рекомендации; для текущей аудиопанели низкий приоритет |
| Концерты | concerts, locations, feeds; требуют региона и отдельного интерфейса |
| Несколько аккаунтов | Токен и библиотека должны выбираться по аккаунту; текущий сервис рассчитан на одну запись интеграции |

## Методы изменения данных

В библиотеке также есть лайки/дизлайки, создание и редактирование плейлистов,
закрепление, предсохранение, настройки аккаунта/волны, feedback, создание очереди,
обновление позиции и авторизация устройства. В рамках обзора они не вызывались.
Для интерфейса особенно полезны лайк/дизлайк трека, добавление в плейлист и
сохранение позиции книги; каждое действие должно явно отражать результат API.

## Очерёдность дальнейшей работы

1. Надёжные пустые состояния, пагинация больших коллекций и понятные ошибки отдельных блоков.
2. Избранные альбомы/исполнители/чужие плейлисты, история и тематические подборки.
3. Полноценная волна с feedback, сохранение прогресса книг и очередь с владельцем-колонкой.
4. Похожие треки, тексты, подробные сведения и управление коллекцией.

Список описывает доступные направления; он не означает, что все перечисленные
функции уже реализованы в текущем релизе.
